BacktrackingHow to undo a change, and what it costs per repo

The four-step path: (1) find the change in the commit index below (filter by keyword, SHA, branch, or doc version) → (2) open the linked doc entry for the story and its sibling commits → (3) git revert <sha> on the commit's home branch → (4) ship the revert through that repo's own path, which is where the real cost lives:

C3suite_server: a push to production-build deploys live immediately. CI is configured to skip that branch, so nothing tests a revert on its way out. The tracked push guard blocks accidental pushes; a deliberate one needs ALLOW_PROD_PUSH=1 in front of the command. Prefer branch → PR → merge, exactly like the fixes in v33/v34 did (PR #940, #942).
c3suite-web: a push to main publishes the live website within minutes (AWS Amplify rebuilds on every push; no CI, no approval step). The only undo is another push. Same guard, same ALLOW_PROD_PUSH=1 override. Two things here look unused and are not. Android builds in customers' hands depend on the /api/* rewrite (see v15), and the middleware's login behavior stops a crash loop. Reverting either breaks customers.
c3app: a push deploys nothing, but a shipped build cannot be un-shipped. Store builds in customers' hands are immutable; a mobile "rollback" means revert on the product branch → rebuild → resubmit → days of store review. Corollary: the API::V1 request/response shapes those builds call are frozen. A server-side revert that changes v1 behavior is itself a breaking change for the field.
Fixes on c3app usually land in triplets. One feature or fix = three near-identical commits, one per product branch (see v14, v20, v24, v25). Reverting one branch's copy leaves the other two live. The index's description column names the siblings; revert all three or none.

The website restyle gets the review it never had, and goes up as a pull request

The restyle branch had been marked complete on August 13, but its own done-condition, a pull request into the integration branch, was never met. An earlier pull request (#6) was opened and closed without merging. So the branch was treated as unreviewed and taken through a full pass. It was first brought up to date with the integration branch, which had moved on by three merges. Three genuine defects came out of the walk-through, each confirmed by measuring the page rather than by eye. The product cards' buttons did not line up, because the rule meant to pin them to the bottom of each card was inert.

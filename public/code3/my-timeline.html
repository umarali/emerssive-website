July (3 days)

July 6 and 7: I started writing the work down. Every session now ends with a short summary in plain words, kept in the repo, so what happened is not only in my head. Three of those exist so far. The same two days went on setting Claude up to work in our code safely.

July 30: the branch our server deploys from was broken, and I had it fixed. A file at the tip of that branch had a syntax error sitting there since June, so the next deploy would have failed on its way out. It was fixed and tested on my machine, together with the Rails version bump we owe, until the test suite came back clean. It stayed on a local branch and never went out on its own.

August (9 days)

I had the customer website gone through end to end. Security, purchases, quiz scoring, the lot. It turned up real problems: paid course content that is not actually locked behind a purchase, in-app purchases the server takes on trust, and quiz scores that come out wrong because answers get dropped on submit. Ten write- ups, ordered by what to fix first. None of it is fixed yet; this was about knowing.
server PR #946, merged10 reports kept in the repo
Rules and a safety catch in all three repos. Each repo now tells Claude how to work in it, and a guard blocks any push to a branch that goes live. On the server, merging and deploying became two separate steps, so nothing reaches customers unless I say go. Status moved to Asana instead of sitting in files nobody opens.

Seven server pull requests, all merged with tests passing. Everything above went in as a pull request someone can read, not a direct push. One test that failed at random got tracked down and properly fixed, rather than run again until it passed. Five known security warnings in the libraries we depend on are written down as work still to do.

A purchase bug in two of the apps. Restore Purchases could unlock a course somebody never bought, because the app accepted any earlier purchase instead of the matching one. Both apps now check for that exact product, which is what the EMT app already did. Merged, so it goes out with the next store builds; customers do not have it yet.

What to do about four mobile codebases. We publish three apps, not four; the fourth branch is a leftover nobody ships. Instead of making every fix three times, the plan is one codebase with three flavours, rolled out Interview first, then EMT, then Fire, each behind a short test list. Decided and written down, not started.

Cheaper models doing the routine work. The strongest model now plans and reviews, and smaller ones do the searching and the mechanical edits, each in its own copy of the repo so they cannot trip over each other. I have not measured what it saves yet.

The website redesign, first pass. The site got a proper set of building blocks, meaning fonts, colours and spacing defined once and used everywhere, and the marketing pages were rebuilt on top of them. Eleven commits on a working branch. Nothing a customer can see.
the restyle branchweb PR #7, merged
Three fire courses were showing the wrong price. The Fire app fills a gap in the server's course list with prices written into the app itself, and one of them had drifted to the wrong tier. The cause was an admin screen that quietly stopped saving that list. The database fix is tested both ways and merged, and it applies itself on the next deploy.
server PR #950, mergedmerged, not live
The redesign got the review it never had. It had been called finished without anyone actually reviewing it, so I had it walked through properly. Three real problems came out: buttons that did not line up on the course cards, and a mobile menu that let the page scroll behind it and the keyboard wander into the page underneath. Fixing the menu left its own close button unreachable, which Codex caught.
web PR #8, open2 review rounds, 1 finding
Restyle finished: new logo, real app screenshots, rebuilt course page. After I called the first attempt generic, the design rules themselves were fixed first, since those rules were what produced the look. The logo was redrawn as shapes so it holds at any size, and the site got its first favicon and link preview. The drawn phones were swapped for our own App Store screenshots and the course page rebuilt. Both pull requests are open.
web PR #8, openserver PR #951, openweb PR #9, open
One set of colours per course family, and app pictures taken from the real apps. Each app paints itself from a record on the server, and those records had drifted apart: the same family red in one place, blue in another. It is now one set per family, as a database change that can be undone and was tested both ways on a copy of our database. The pictures on the site were re-taken from the apps as they run now. All of it is pushed, not merged.
server PR #952, openapp PRs #114 to #117, openre-shot screens in web PR #8
The 18 August work got its review the same day. A separate Claude review went over it in five lanes, with a second agent trying to knock down every finding before anything changed. Nine came through, all small, all fixed and pushed the same evening: the colour change now replaces a broken colour record instead of stopping the deploy, and the register's claims now match the code. The app register copy on main went up as its own pull request. Nothing merged.
server PR #952, openweb PR #8, openapp PR #122, open
The second reviewer got its turn at last, and found nothing. The reviewer locked out on 18 August came back a day early and read the colour change and all four app changes against their real branches. Five reads, nothing to fix. I had the app changes read line by line first as well, to be sure no screen can draw itself before its colours arrive. The last copy of the colour register went onto the app's main branch, so all seven match.
server PR #952, openapp PRs #114 to #117, openregister on app main
The first of the three big security problems has a fix, on my machine only. In-app purchases could be forged: three requests and any account got any course free, for good. The fix refuses a purchase receipt already used by another account or another course. It sits behind a switch and only writes to the log for now, so no real customer restoring a purchase is turned away before we have read a week of those lines. Still on my machine, not pushed.
fix/iap-transaction-id-guard, not pushed
A broken bar in the app was nearly published on the website. On the quiz and results screens the coloured header stops short and steps in at both sides. It has been there since 2020 and has nothing to do with the missing brand font, which turns out to be absent on both phones, not just iPhone. Fixed on all four apps, and the six website screenshots re-shot from the fixed build. Screenshots pushed, apps still on my machine, live with the next store build.
